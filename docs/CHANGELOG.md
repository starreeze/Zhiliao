### 三个独立开关

三个开关默认关闭，并受总开关控制。打开后重启知乎生效。

| 场景 | 配置键 | 行为边界 |
| --- | --- | --- |
| 首页推荐信息流 | `switch_filter_paid_recommend` | 仅处理推荐页，不以正文关键词、作者会员身份或评论关闭作为付费判定 |
| 问题下的回答列表 | `switch_filter_paid_question` | 删除确认属于付费内容的回答，保留普通回答和真实分页状态 |
| 打开回答后的连续浏览流 | `switch_filter_paid_browser` | 保留用户明确打开的回答，只过滤后续信息流项目；正文展开分页不作为回答列表过滤 |

模型覆盖、空页处理及现场验收范围见下文[手机验证记录](evidence/2026-11-10-betterzhiliao-v0.2/README.md)和[三场景调查](history/2026-11-10-premium-three-scenarios.md)。开关存在不等于每个入口和边界均已验证成功。

### 信息流广告与启动弹窗

两个新增开关受 BetterZhiliao 总开关控制，默认开启。`switch_launchad` 仍负责原有启动页广告；新启动弹窗开关作用于首页透明视频广告入口，不改变启动页路径。

| 场景 | 配置键 | 默认值与作用范围 |
| --- | --- | --- |
| 首页悬浮图片广告 | `switch_floatad`（去悬浮广告） | 开启；拦截 `AdFloat` / `AdFloatSecond` 首页图片广告判断，并清理由 `AdFloatVideo.endVideo(int)` 创建的广告挂件。第一屏无缓存时仍保留原生完成回调。 |
| 启动透明视频弹窗 | `switch_popupad`（去启动弹窗广告） | 开启；当继承配置及 `config.a` 广告对象都存在时，在 `AdFloatVideo.startAlphaVideo()` 入口阻止透明视频广告活动启动，覆盖缓存视频、图片回退和切换标签触发的该入口；同时调用原生一次性完成回调 `d.a(0)`。若配置或广告对象为空，则保留原生启动与完成流程。 |

范围仅限这些明确的广告控制器路径；通用 `GlobalPopup`、`GlobalDialog` 和导航流程不变。挂件清理调用原生 `remove()`，以释放计时器并移除广告视图。启动弹窗被抑制时仍发送原生一次性完成事件；缺少配置或广告对象时保留原生处理。实现见 [`FloatingAd.java`](../app/src/main/java/com/shatyuka/zhiliao/hooks/FloatingAd.java) 和 [`PopupAd.java`](../app/src/main/java/com/shatyuka/zhiliao/hooks/PopupAd.java)。DEX 方法签名核对和独立代码复核通过。

当前代码检查结果：现有 54 项单元测试通过，`assembleDebug` 与 `assembleRelease` 通过；54 项测试覆盖过滤、分页等核心逻辑，不代表新增广告钩子通过了广告专属单元测试。广告钩子另经 DEX 方法签名核对、独立代码复核、生产构建及安装标记验证；APK 的应用 ID、版本 `0.2` / `202602032` 和签名已核对。

### 自定义过滤修复

知乎 11.5.0（40530）的推荐卡片可以使用 `HtmlTextElement`。该类型与 `TextElement` 为不同模型；以 `TextElement` 的反射字段读取 HTML 元素会抛出异常，使后续过滤中断。

修复在读取卡片内部文本前执行类型过滤，并按实际元素类型读取普通文本或 HTML 文本。这样视频、文章、想法等类型过滤不再依赖文本提取能否成功，HTML 文本也可参与正则过滤。

### 持续加载修复

原“禁止自动刷新”逻辑还拦截了推荐流共享的加载生命周期：取消 `nextUrl` 为空的预加载，并阻止加载完成回调。这些入口也参与正常分页或刷新；拦截后可能遗留未完成状态，表现为持续转圈。

修复移除这两类共享生命周期拦截，保留明确的旧版定时刷新、切换标签刷新触发点拦截。新版未知刷新路径能否被禁止，需要另行验证；本次不以破坏正常加载完成流程来实现该开关。

### 构建与安装

使用项目 Gradle wrapper 和 JDK 17 构建：

```sh
bash ./gradlew testDebugUnitTest \
  --tests com.shatyuka.zhiliao.HookTest.customFilterTest \
  --tests com.shatyuka.zhiliao.HookTest.autoRefreshTest
bash ./gradlew assembleDebug assembleRelease
```

正式包输出为 `app/build/outputs/apk/release/BetterZhiliao_0.1.apk`。配置 `releaseStoreFile` 等签名属性时使用指定签名；未配置时沿用项目现有回退逻辑，使用本机 `~/.android/debug.keystore`。这属于本地调试签名，不能视为上游或应用商店正式签名。密钥和口令不应进入仓库或文档。

当设备上已有的模块签名不同时，直接覆盖安装会失败。若需更换签名，卸载与重新安装的对象仅限 BetterZhiliao/知了模块本身，并须重新检查模块启用状态、知乎作用域和模块设置；不要卸载知乎或清除知乎数据。相同签名的后续 APK 可直接更新。CI 未配置共享签名时使用临时运行环境中的调试签名，不保证与本地发布包的签名相同。安装后须重启知乎进程，让代码与资源一同重新加载；仅替换文件不足以验证新版本生效。
