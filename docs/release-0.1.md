## 自定义过滤修复

知乎 11.5.0（40530）的推荐卡片可以使用 `HtmlTextElement`。该类型与 `TextElement` 为不同模型；以 `TextElement` 的反射字段读取 HTML 元素会抛出异常，使后续过滤中断。

修复在读取卡片内部文本前执行类型过滤，并按实际元素类型读取普通文本或 HTML 文本。这样视频、文章、想法等类型过滤不再依赖文本提取能否成功，HTML 文本也可参与正则过滤。

## 持续加载修复

原“禁止自动刷新”逻辑还拦截了推荐流共享的加载生命周期：取消 `nextUrl` 为空的预加载，并阻止加载完成回调。这些入口也参与正常分页或刷新；拦截后可能遗留未完成状态，表现为持续转圈。

修复移除这两类共享生命周期拦截，保留明确的旧版定时刷新、切换标签刷新触发点拦截。新版未知刷新路径能否被禁止，需要另行验证；本次不以破坏正常加载完成流程来实现该开关。

## 构建与安装

使用项目 Gradle wrapper 和 JDK 17 构建：

```sh
bash ./gradlew testDebugUnitTest \
  --tests com.shatyuka.zhiliao.HookTest.customFilterTest \
  --tests com.shatyuka.zhiliao.HookTest.autoRefreshTest
bash ./gradlew assembleDebug assembleRelease
```

正式包输出为 `app/build/outputs/apk/release/BetterZhiliao_0.1.apk`。配置 `releaseStoreFile` 等签名属性时使用指定签名；未配置时沿用项目现有回退逻辑，使用本机 `~/.android/debug.keystore`。这属于本地调试签名，不能视为上游或应用商店正式签名。密钥和口令不应进入仓库或文档。

当设备上已有的模块签名不同时，直接覆盖安装会失败。若需更换签名，卸载与重新安装的对象仅限 BetterZhiliao/知了模块本身，并须重新检查模块启用状态、知乎作用域和模块设置；不要卸载知乎或清除知乎数据。相同签名的后续 APK 可直接更新。CI 未配置共享签名时使用临时运行环境中的调试签名，不保证与本地发布包的签名相同。安装后须重启知乎进程，让代码与资源一同重新加载；仅替换文件不足以验证新版本生效。
